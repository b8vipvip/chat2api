# Worker 工具中心与证据探针平台：实施状态

设计基准：[技术实现方案 v1.0](worker-tools-probe-platform-design-v1.0.md)。

## P0：已实现（正式版 v0.22.168）

- 全局策略、单 Worker 策略，配置修订号与默认关闭。
- 图片交付与聊天 DOM 探针：请求前、媒体生成过程、长时间未确认和终态前记录结构化证据。
- `request-v6` 与 `image-v3` 分别负责原有业务终态，探针不得发送 `chat.completed`、`chat.error`、`image.completed` 等控制事件。
- 管理员请求记录/Worker 工具中心关联诊断证据与 ZIP 导出；按请求 ID 限定证据归属，默认不保存正文、Cookie、图片二进制或签名链接。

## P1：当前分支进行中（尚未正式发布）

- `network_evidence_v1`：复用已存在的网络流计数，读取网络流是否出现、字节数、事件数、终态存在性、未验证中断及距最后一包的间隔。**不**截取请求或响应原文。
- `model_tool_state_v1`：只统计模型切换、推理控件、工具入口、附件和图片编辑控件的命中数量，不读取页面实际账号或模型文字。
- `selector_compat_v1`：统计输入框、发送/停止按钮、消息回合、图片节点等关键选择器命中数量，便于对比页面改版。
- 所有开启的探针共享最多 32 个事件的请求级预算，并为终态前采样预留容量。一个工具没有证据应标记 `not_collected`，不得假报通过。
- 仍需 CI 及 TX03 实机核验；网页仅能看到大图并不意味着已取得可交付图片字节。

## P2：尚未开发

全局模板复制与灰度推送、截图/视频安全脱敏证据、长期版本差异自动分析、更丰富的任务类型探针、配置审计与维护工具等。

## 复测建议

1. 服务端与 TX03 Worker 同步升级到正式版，并验证 `/version` 的 Server/Bundle 版本一致。
2. 在 **Worker 工具** 中对 TX03 开启所需探针，再发起新请求；旧请求不能补采证据。
3. 普通对话（文本模型触发图片工具）和专用 `gpt-image` 接口分别测试；记录业务请求 ID。
4. 在 **请求记录 → 查看对话 → 查看探针** 查看采样条数，再到 **Worker 工具** 下载该请求证据 ZIP。
5. 将失败请求的 ZIP、服务端运行日志与可见的 ChatGPT 页面截图一并用于根因分析。

**重要：** 当前探针是诊断基础设施，不改变原本的图片交付算法，不承诺自动修复 ChatGPT 图片超时。
