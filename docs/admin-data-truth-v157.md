# 管理控制台数据真实性审计（v0.22.113）

本次审计聚焦“真实的 0”与“没有取得数据”被混为一谈，以及设备/Worker 关联使用任意记录的问题。

## 修复内容

- **Worker 请求数**：`active_api_calls` / `capacity.used_units` + ` 由服务端从 RequestBroker 的活动请求索引计算；当请求计数来源不可用时不伪造 `0`，前端显示 `?`。
- **窗口实时核验**：服务端不再仅凭一个更新的 `updated_at_ms` 就认定核验成功，而是等待同一 `control_id` 的 `window.manager.refresh.result`，并核对回执时间与物理快照时间。核验结束时 Worker 仍必须在线，才会发布实时窗口数。
- **浏览器窗口枚举失败**：Chrome `windows.getAll()` 的异常不再被吞掉并转换为空数组，避免把 API 暂时不可用错误地显示为 0 个窗口。失败时保留上次数据但不产生新的实时核验回执。
- **窗口管理汇总**：只核验了部分在线 Worker 时，显示“已核验备用窗口”，并明确指出未核验 Worker；缺少汇总字段时显示未知，而不是默认 0。
- **Windows 设备列表**：网络信息优先关联到具有数据的在线 Worker；设备操作目标优先选择最新在线的绑定 Worker；“最后在线”只使用 Worker 心跳时间，不再把配对时间误当作最后在线。
- **Linux Worker 状态**：`ready` 但没有有效心跳时间时显示“等待心跳”，不再直接显示绿色正常；离线/缺少登录遥测时，ChatGPT 状态显示未知，而不是误报未登录。

## 数据语义

- `0`：已取得可信来源的数据，结果确实为零。
- `?`：没有可用的实时/可信数据。
- “上次报告 / 上次核验”：只表示缓存中的最后一次可信观测，不代表当前物理状态。
- 配置目标（如 `max_windows`）不是实时物理窗口数量，不能作为实际容量展示或调度依据。

## 回归覆盖

`tests/test_admin_data_truth_v157.py` 覆盖窗口刷新回执匹配、无回执/错误回执、Worker 在核验后离线、未知计数以及窗口枚举异常语义。`tests/admin_device_data_truth_v157.mjs` 覆盖 Windows 设备多 Worker 时的在线优先、网络数据来源和最后在线关联。Worker 活动请求数测试覆盖活动索引为空但主请求索引仍有请求的回退场景。
