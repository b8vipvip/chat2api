# chat2api v0.22.53

- Server Runtime: `0.22.53`
- Chrome Worker Bundle: `0.8.23`
- Bridge Protocol: `0.8.1`

## Fixes

1. Multimodal Safe Submit v85 adds a conservative post-upload quiet window (8s up to 512 KiB, 12s up to 2 MiB, 18s above 2 MiB) after the existing v78/v84 checks, and additionally detects CSS pseudo-element and SVG animation upload indicators. This closes the timing race where v84 reported `busy_seen=false` while the visible ChatGPT attachment spinner was still finishing.
2. Same-API-key routed conversations now stay alive for five idle minutes. Both the conversation router and reserve supervisor use the same 300-second deadline.
3. Tab Supervisor now treats `reserve_window_target` as a spare-window target instead of a total-worker cap, so an idle routed affinity conversation cannot be reclaimed immediately after a terminal event. Existing safety rotation budgets remain 32 turns / 96,000 text chars / 16 attachments.
4. All managed ChatGPT window creation paths share one global 15-second start interval, preventing reserve/warm/routed/bootstrap windows from opening in a burst.
