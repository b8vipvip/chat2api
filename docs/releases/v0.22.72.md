# chat2api v0.22.72

## FDEX / Codex full-smoke compatibility

- Responses tool-stream v116 recovers the real malformed custom `exec` envelope observed during FDEX full smoke: a nested `arguments: {name, input}` payload whose raw JavaScript contains unescaped quotes.
- Recovery remains fail-closed: the normalized call still passes through the existing request tool catalog and allowlist before it can become executable.
- This closes the gap between the v113 raw-custom recovery, v114 nested custom normalization, and v115 nested-exec recovery paths.

## Sequential API window affinity

- Worker routing v27 adds a short terminal handoff grace before a same-key sequential request is allowed to spill from Worker #1 to Worker #2/#3.
- A live routed tab is no longer considered sufficient by itself: when the tab has drifted to a different ChatGPT conversation or the root page, the Worker restores the saved conversation URL before dispatching the next request.
- Genuine overlapping active requests still retain the existing same-key parallel Worker behavior.

Acceptance contract for a sequential chain:

`same logical API key -> Worker #1 -> same Chrome window -> same tab -> same ChatGPT conversation`

Worker #2/#3 are used only when another request for the same logical API key is genuinely still active after the bounded handoff grace.

## Request-history observability

- Request History adds a `窗口编号` column.
- Window number, physical Chrome `window_id`, `tab_id`, and route key are persisted into request telemetry.
- Per-request downloaded diagnostics therefore keep the same window correlation evidence even after Responses terminal telemetry is written.
