# chat2api v0.22.70

- Server Runtime: `0.22.70`
- Chrome Bridge protocol: `0.8.1`
- Chrome Worker Bundle: `0.8.28`
- Python package: unchanged

## Responses developer experience

This release promotes the Responses console/docs work merged in PR #235 into the formal runtime contract.

- User console `开发文档` now presents `POST /v1/responses` as the recommended protocol for new integrations while preserving `POST /v1/chat/completions` as backward-compatible.
- Administrator `/developers` receives the same Responses calling contract.
- Documents native `web_search`, emulated `function` / `namespace` / `custom` / `tool_search`, `previous_response_id`, `function_call_output`, `custom_tool_call_output`, `mcp_tool_call_output`, and `tool_search_output` continuation.
- Explicitly documents that external tools remain caller-owned; chat2api transports calls/results and does not pretend to execute shell, apply_patch, or MCP tools.
- User Playground now lets users choose Responses API or Chat Completions. Responses mode can directly validate native Web Search.
- Existing Playground clients that omit the protocol field continue to use the historical Chat Completions path unchanged.

## Compatibility

- `/v1/chat/completions` remains supported with `messages[]` and its existing streaming/non-streaming response shape.
- `/v1/responses` uses `input`, structured `output[]`, `output_text`, and Responses tool continuation semantics.
- Agent/Codex/FDEX integrations that need tool loops should use `/v1/responses` rather than relying on the compatibility Chat Completions endpoint.

## Validation

Release publication remains gated by repository CI and Production image smoke. After merge, the Release workflow creates `v0.22.70` only when the merged `main` commit passes the release gates.
