# chat2api v0.22.69

- Server Runtime: `0.22.69`
- Chrome Bridge protocol: `0.8.1`
- Chrome Worker Bundle: `0.8.28`
- Python package: unchanged

## Responses API

This release promotes the Responses work merged in PR #232 and PR #233 to the formal runtime contract.

- Adds `/v1/responses` and `/v1/responses/{id}` while preserving `/v1/chat/completions`.
- Adds the native ChatGPT Web tool/final lifecycle bridge: `stream_handoff -> WebSocket conversation-turn-* -> nested SSE -> tool/final/completion`.
- Adds native `web_search` / `web_search_preview` mapping.
- Adds caller-owned emulated `function`, `namespace`, `custom`, and `tool_search` transport for FDEX/Codex.
- Adds `function_call_output`, `custom_tool_call_output`, `mcp_tool_call_output`, and `tool_search_output` continuation.
- Keeps external tool execution caller-owned; chat2api transports calls and results instead of pretending to execute shell/MCP/apply_patch.
- Keeps Responses requests inside canonical model routing, telemetry, billing, and API-key owner isolation.

## Worker bundle

Worker Bundle stays at `0.8.28` for this server-runtime release. The already-merged v108 bundle content includes the v63 native WebSocket tool observer and isolated-world transport; v71 runtime preflight explicitly requires those v63 modules, so the Responses native bridge is part of the validated runtime even though the MV3 manifest version is not advanced in this release.

## Validation

Release publication remains gated by the repository release workflow: the merged `main` commit must pass both CI and Production image smoke before GitHub creates tag/release `v0.22.69`.

FDEX `wire -> tools -> full` provider smoke remains the post-release end-to-end acceptance target.
