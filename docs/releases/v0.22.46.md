# chat2api v0.22.46 / Worker 0.8.18

This release fixes the two distinct vision failures observed after the v0.22.45 deployment and publishes a new Worker bundle boundary.

## Version surfaces

- Server Runtime: `0.22.46`
- Chrome Worker Bundle: `0.8.18`
- Chrome Bridge protocol: `0.8.1` (unchanged compatibility surface)
- Python package: `0.7.1` (unchanged)
- Content runtime epoch: `71`
- Multimodal controller revision: `78`
- Current request/response epoch: `69`

## Fixes

### MAIN-world multimodal upload v78

The attachment driver is now split across the extension isolated world and a dedicated ChatGPT page MAIN-world bridge. The MAIN bridge constructs `File`/`DataTransfer` objects using the page realm, uses the native `HTMLInputElement.files` setter, and dispatches the file-input, paste, and drop paths from the same JavaScript realm as the ChatGPT composer.

The isolated controller retains strict upload confirmation: filename/chip/preview evidence, DOM mutation evidence, upload-progress/error detection, duplicate-dialog recovery, and suppression of repeated injection after any strong upload signal. A missing/generic MIME type is also normalized from the filename before browser injection.

Worker runtime preflight now requires both multimodal revision 78 and the MAIN-world marker. Existing ChatGPT tabs that still own an older v68 controller are reloaded into the 0.8.18 content epoch rather than running two attachment owners concurrently.

### Structured Worker model-capability routing v2

Production `ClientRegistry.client_models()` returns structured model dictionaries. The previous routing guard stringified those dictionaries, so an online Linux Worker advertising `gpt-5.5` could be incorrectly rejected for the `gpt-5.5-mini` compatibility route before a vision request was dispatched.

The router now extracts normalized model ids from structured entries (`id`, `model`, or `family`) while retaining compatibility with legacy string catalogs. Regression coverage verifies that an `account_type=unknown` Linux Worker advertising structured `gpt-5.5` capabilities can receive a `gpt-5.5-mini` vision request.

## Compatibility

Worker `0.8.18` is a real bundle boundary. The manifest, legacy v48 marker/contract, v71 marker/contract, bootstrap path, and background runtime preflight all advertise or require `0.8.18`. The Chrome Bridge wire protocol remains `0.8.1`, so this is a Worker implementation/runtime upgrade rather than a wire-protocol break.
