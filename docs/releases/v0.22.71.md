# chat2api v0.22.71

- Server Runtime: `0.22.71`
- Chrome Bridge protocol: `0.8.1`
- Chrome Worker Bundle: `0.8.28` (unchanged)
- Python package: unchanged

## FDEX / Codex alignment

This release packages all validated mainline fixes after v0.22.70 so the normal GitHub server update can reconcile the deployed server and Worker payload as one release boundary.

- Responses tool-stream v115 recovers GPT-5.6 Sol nested collaboration calls (`spawn_agent` / `wait_agent`) only when the nested tool is explicitly declared by the allowlisted custom `exec` catalog; unknown nested tools remain fail-closed.
- Carries Worker router terminal-reuse revision 26 so sequential Responses/Codex continuations can reuse the original logical API-key route instead of spuriously spilling to `::worker2`.
- Worker bundle semantic version intentionally remains `0.8.28`. The existing post-deployment Worker auto-sync compares old/new Git commits and forces Worker refresh when Worker payload changed even if bundle semver is unchanged.
- `/version` advertises `responses_tool_stream_v115=true` and `worker_terminal_reuse_v26=true`, plus explicit build/feature revision markers for deployment verification.

## Validation and rollout

- Release publication remains gated by repository CI and Production image smoke.
- Updating the server from GitHub to this release invokes the existing post-deployment Worker reconciliation; Worker-impacting diffs are refreshed even with bundle `0.8.28`.
- After update, actual Worker runtime diagnostics should show router revision 26 and terminal-reuse diagnostics on routed requests.
