# chat2api v0.22.54

- Server Runtime: `0.22.54`
- Chrome Worker Bundle: `0.8.24`
- Bridge Protocol: `0.8.1`

## Fixes

1. Worker disable now owns managed-window creation as well as teardown. After `worker.disable` collapses the Worker to one managed ChatGPT window, v86 blocks reserve/warm/routed refill attempts and closes any delayed window whose staggered creation completes after the disable flag becomes authoritative.
2. Successful text/image terminal events no longer recycle an otherwise healthy routed conversation merely because the content controller needs longer than the short terminal-settle observation window. Failed/cancelled routes are still quarantined and recycled. This restores the intended five-minute same-API-key conversation affinity from v0.22.53.
3. Runtime preflight now probes the already-loaded v71 contract first and takes a bounded `current-fast-path-v86` when a prewarmed tab is current. The contract/tool-isolation probes are bounded to 1.2 seconds; only stale/incomplete tabs enter overlay repair or reload repair. This removes the redundant per-request repair path that could delay prompt insertion by tens of seconds.
4. Request-history prompt viewing is repaired against the current table renderer. The v86 console layer recovers request IDs from the row itself or any request action, creates/repairs the `提示词` cell after dynamic table repainting, and keeps `查看提示词` / copy behavior bound to the audited `final_prompt` detail endpoint.

## Preserved behavior

- Multimodal Safe Submit v85 remains enabled, including the conservative post-upload quiet window.
- Managed ChatGPT window starts remain globally staggered by at least about 15 seconds.
- Routed conversation safety budgets remain 32 turns / 96,000 text chars / 16 attachments with a five-minute idle deadline.
