# chat2api v0.22.75

Server Runtime `0.22.75` and Chrome Worker Bundle `0.8.31` close the remaining failure path after the v0.22.74 single-authority scheduler/window refactor.

## Unexpected routed-window failure

- `conversation_routing.js` revision 30 remains the only authority that creates, reuses, rotates, retires or idle-closes routed ChatGPT windows.
- New `background_route_close_terminal_v91.js` is terminal-report-only. It does not create, close or mutate route/window lifecycle state.
- If an active routed tab or window disappears unexpectedly, v91 immediately reports the matching `chat.error`, `image.error` or `voice.error` to the server.
- The terminal report lets server scheduler v58 release the logical API key immediately instead of leaving the single active slot occupied until a watchdog or request timeout.
- The retired `background_request_recovery_v40.js` remains out of the production entrypoint, so the fix does not reintroduce a second window lifecycle owner.

## Worker runtime alignment

- Chrome Worker Bundle: `0.8.31`.
- Manifest, v48/v71 bundle markers, v48/v71 content contracts and bounded runtime preflight all require `0.8.31`.
- `/version` exposes `route_close_terminal_revision=91` and `unexpected_route_close_terminal_v91=true`.

## Production validation

The production-image smoke verifies the generated Worker bundle contains the terminal-only v91 reporter, confirms it cannot create/close windows, checks the v30 router remains the lifecycle authority, boots `app.entry:app`, and verifies `/version` reports Server Runtime `0.22.75` and Worker Bundle `0.8.31`.

The v58 server FIFO, v30 route authority, v90 observer, Responses Tool Stream v118 and existing multimodal/native-tool stack are carried forward unchanged.
