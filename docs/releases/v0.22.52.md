# chat2api v0.22.52

- Server Runtime: `0.22.52`
- Chrome Worker Bundle: `0.8.22`
- Bridge Protocol: `0.8.1`

## Fix

Windows Worker multimodal uploads now wait for the real ChatGPT attachment readiness boundary instead of treating the first visible thumbnail as proof that upload/processing completed. The v84 ready gate detects semantic upload indicators and visible CSS animation spinners inside the attachment tile, requires the attachment to remain present and non-busy for a stable interval, and emits explicit waiting/ready/timeout diagnostics. This prevents the prompt from being submitted while the image thumbnail is still spinning, which previously caused ChatGPT to clear both the prompt and attachment without creating an accepted user turn.
