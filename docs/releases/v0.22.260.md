# chat2api v0.22.260 — Request-scoped native content validation

## Included in this release

1. Worker request-v6 now positively binds a fresh assistant response container to the current request using a pre-send DOM baseline, a post-submit network response, and newly displayed answer action controls before promoting native content.
2. Native rich snapshots refuse to claim full-structure delivery when the request-local assistant boundary is unverified. Standard OpenAI text completion remains independent and retains sole-terminal ownership.
3. Deep answer layouts (more than 35 nested DOM levels) can establish safe toolbar ancestry, while user prompts, chat-wide containers, old response toolbars and ambiguous reply scopes remain excluded.
4. Diagnostics expose bounded request-scope verification flags and binding stage; no raw prompt, cookie, signed image URL or DOM HTML is emitted by these flags.

## Status and scope

This is an **incremental validation release**, not a claim that ChatGPT native rich content is already visually or structurally 1:1. Future work is still required for in-progress subtree mutation observation, safe high-fidelity HTML/CSS rendering, original image and attachment byte archiving, and end-to-end visual regression.

## Recommended real Worker acceptance

- Verify the request ID and its fresh response scope are unique to the current tab/session.
- Compare long rich responses (tables, code, multiple images and file cards) against the actual ChatGPT page and native content preview; do not score only by request completed.
- Confirm native snapshot revisions are server-ACKed; when no bound reply scope exists the API must not receive partial native content marked as final.
- Confirm streaming, request cancellation and voice are unaffected.

The independent historical-page diagnostic tool remains versioned and released separately; its prior source branch has not been merged into runtime code by this release.
